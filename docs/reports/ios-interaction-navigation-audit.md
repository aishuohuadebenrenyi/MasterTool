# iOS 按钮与导航层级审计

## 当前规则

- iPhone 底部 Tab Bar 仅在首页、备课、我的三个根页面显示。
- 方案、活动、现场、反馈、复盘、记录、数据、设置、帮助、关于和隐私等二级页面统一隐藏 Tab Bar；返回根页面后恢复。
- iPad 继续使用三项侧栏作为一级导航，不改成底部栏。
- iPhone 半弹窗统一使用右上角圆形关闭按钮；关闭不提交数据。
- 选择结果需要进入新页面时，先关闭半弹窗，再通过所属 Tab 的 `NavigationStack` 跳转。
- 同一功能页最多维护一个 sheet 状态；iPad 现场工具使用右侧检查器。
- 系统错误 Alert 属于失败反馈，不计为业务弹窗嵌套。

## 已修复交互

| 入口 | 原问题 | 当前行为 |
| --- | --- | --- |
| 首页 → 从我的方案 | 弹窗内再次弹出方案列表 | 关闭弹窗后切换备课，筛选我的方案与已确认；无已确认时回退草稿 |
| 首页 → 公共模板 | 在弹窗导航栈内进入编辑，编辑页还能继续弹窗 | 关闭弹窗后进入首页普通方案编辑页面 |
| 备课 → 新建方案 | 模板弹窗内进入编辑或详情 | 选择模板并关闭弹窗后进入备课普通导航页面 |
| 备课 → 新建活动 | 先打开只有一个“新建活动”选项的冗余弹窗 | 直接进入普通活动编辑页面，不创建 sheet |
| 方案编辑 → 预览 | 以第二个 sheet 展示 | 改为普通页面 push |
| 活动详情 → 编辑 | 以 sheet 展示且保存不回写 | 改为普通页面 push，保存后回写当前页面与本地活动列表 |
| 方案环节 → 添加活动 | 所有入口都写入第一个环节 | 按触发按钮携带的 `phaseId` 写入目标环节 |
| 备课筛选 | 来源、类型、场景绑定常量 | 改为真实状态并参与列表过滤 |
| 方案卡 | 开课按钮嵌套在整卡 NavigationLink 中 | 查看与开课拆分为独立按钮 |
| 现场工具/结束 | 两套 sheet 状态可能并存 | 合并为单一枚举状态；iPad 只更新检查器 |
| 设置 → 微信账户 | 进入无法提交的绑定弹窗 | 改为不可点击的“即将支持”状态，不再制造交互死路 |
| 设置 → 现场偏好 | 开关只保存值，不影响现场行为 | 左右滑动、双击加时和计时结束提醒均接入现场页；自动保存改为只读状态 |

## 方案编辑对齐

- 基本信息使用与小程序相同的白色卡片层级，包含方案名称、参与人数减加控件、客户名称和方案类型标签。
- 环节设置使用循环彩色编号、可编辑名称与时长、活动数量、活动明细、移除、上下移动和删除操作。
- 草稿态底部显示“保存草稿 / 确认方案”，确认态显示“保存修改 / 开始培训”；开课使用成功绿色。
- 添加环节与活动选择继续使用单层原生半弹窗；重复活动不会再次加入同一环节。
- iOS 尚无个人模板保存服务，因此不展示不可执行的“设为个人模板”入口。

## 保留的单层半弹窗

- 选择开课入口
- 选择方案模板
- 从活动库添加
- 现场工具
- 结束培训
- 编辑资料

上述弹窗均提供右上角圆形关闭按钮，不再从弹窗内容触发另一个 sheet。

## 尚未接入的服务能力

以下操作当前没有完整客户端服务契约，因此保持禁用或仅显示状态说明，不清空输入、不关闭页面、不提示成功：

- 微信绑定码兑换（设置页仅显示“即将支持”）
- 帮助与反馈提交
- 数据导出
- 账户及业务数据删除

活动新建、更新与删除已通过 iOS Repository 复用 `trainer.saveActivity`、`trainer.getActivityDetail` 和 `trainer.deleteActivity`；其他以上能力需要另行扩展并联调 CloudBase。
