# iOS 现场全链路与跨端布局收敛 Requirements

## 1. 问题与目标

当前 iOS 现场页在 Debug Mock 下可演示，但真实 CloudBase 开课、保存和结束契约不闭合；部分工具只有本地占位能力，环节计时和 iPhone 半屏交互存在运行态缺陷，页面层级也未与小程序的现场操作优先级对齐。

本次目标是在不改变小程序既有 action 语义的前提下，让 iOS 现场页具备可验证的真实数据链路、明确的本地工具边界、稳定的异步状态和 iPhone/iPad 原生布局。

## 2. 用户故事

1. 作为培训师，我希望开课后加载完整场次快照并可随时恢复，以免现场操作依赖一次性的本地状态。
2. 作为培训师，我希望签到、分组、积分、随机、互动和笔记的成功提示对应真实服务端结果，以免数据在退出或跨端后丢失。
3. 作为培训师，我希望主计时和独立计时与当前环节严格一致，以免控场时间错误。
4. 作为培训师，我希望高频工具和环节导航固定、清晰、可触达，以便在现场快速操作。
5. 作为参与者，我希望继续从微信小程序码或链接进入签到和互动，不改变既有参与者入口。

## 3. 功能需求与验收标准

### R1. 运行时数据源边界

- 当 Debug 未配置 HTTPS 网关或令牌时，iOS 应使用固定 Mock 数据，并明确保持冷启动恢复种子的行为。
- 当 Release 未配置 HTTPS 网关或令牌时，iOS 应显示不可用错误，不得回退 Mock。
- 当真实网关已配置时，现场所有服务端能力应只经 `ios-api` 转发现有业务 action，不得从 iOS 直连 CloudBase 数据库。

### R2. 开课、加载与恢复

- 当培训师开课时，iOS 应先调用 `live.startSession` 获取 `sessionId`，再调用 `live.getSessionDetail` 与参与者/互动列表 action 组装完整现场状态。
- 当服务端存在同方案运行中场次时，iOS 应进入该场次并恢复已保存的分组、积分、随机和当前环节状态。
- 当场次或方案快照无效时，iOS 应保留当前页面并显示可理解错误，不得进入半初始化现场页。

### R3. 写入一致性与错误处理

- 当用户执行服务端现场操作时，系统应调用对应细分 action，并只在成功响应后确认最终状态；允许必要的乐观展示，但失败时必须回滚。
- 当连续操作产生多个请求时，系统应串行化同一场次写入或拒绝旧响应覆盖新状态。
- 当请求失败时，系统应保留可重试状态并显示错误；不得用空 `catch`、假成功或静默丢失替代。

### R4. 环节推进与主计时

- 当环节 index 改变时，主计时应立即使用新环节时长重置，停止旧计时，且不得出现前后环节时长互换。
- 当培训师使用按钮或已启用的左右滑动切换环节时，两种入口应产生相同状态结果。
- 当当前环节 index 需要服务端恢复时，iOS 应通过既有场次更新 action 或最小必要的后端扩展持久化该字段。
- 当计时结束且提醒已启用时，系统应只播放一次提醒。

### R5. 签到

- 当打开签到工具时，iOS 应加载真实参与者列表，显示已签到/预计人数、最近签到和参与者入口。
- 当培训师手动补录姓名时，iOS 应调用 `live.manualCheckin`，阻止空姓名和重复姓名，并以服务端 ID 回显。
- 当培训师请求入口时，iOS 应调用 `live.getSessionEntryCode`，展示小程序码、路径和可复制链接。

### R6. 分组

- 当参与者列表变化且尚未确认分组时，iOS 应能按人数均分或随机生成本地预览。
- 当培训师确认分组时，iOS 应调用 `live.saveGroupState`，保存队伍数量、方式、颜色、成员和确认状态。
- 当保存失败时，已确认分组状态不得留在 UI 中。

### R7. 积分

- 当已完成分组时，iOS 应支持简化和详细积分模式，并调用 `live.saveScoreState` 保存队伍分数。
- 当详细模式加减分时，系统应保存原因与积分流水；失败时应回滚分数和流水。
- 当培训师重置积分时，系统应二次确认并保存所有队伍归零及流水清空结果。

### R8. 随机

- 当抽取参与者或题目时，iOS 应显示当前结果和最近历史，并支持是否允许重复。
- 当随机类型、重复策略、结果或历史变化时，iOS 应调用 `live.saveRandomState` 持久化，失败时恢复上一次服务端状态。
- 当无可抽取参与者时，系统应显示明确空状态。

### R9. 互动

- 当创建词云、投票或承诺互动时，iOS 应调用 `live.createInteraction` 并加载服务端互动列表。
- 当培训师查看互动时，iOS 应能生成/复制参与者入口、查看统计并关闭互动。
- 当投票选项无效或请求进行中时，系统应阻止重复创建。

### R10. 独立计时与音效

- 当使用独立计时时，iOS 应支持正计时、常用倒计时、暂停、重置和加时，并在 sheet 关闭后保持本场运行状态。
- 当培训师点击欢呼、鼓掌、铃声或主题时，iOS 应播放对应本地音频；播放失败时应使用触感降级。
- 本地计时与音效不得产生不必要的 CloudBase 写入。

### R11. 笔记

- 当保存笔记时，iOS 应调用 `live.saveNote`，提交 `sessionId`、当前 `phaseName` 和内容。
- 当保存成功时，iOS 应显示环节、内容和时间；失败时应保留编辑内容。
- 当重新进入现场时，若后端当前没有笔记列表 action，系统应明确本次会话内回显边界，不伪装为已完整恢复。

### R12. 结束培训

- 当培训师确认结束时，iOS 应调用 `live.endSession` 并等待成功，后端应以事务更新场次为 ended、方案为 delivered。
- 当结束失败时，iOS 应保持现场页和运行中状态，并允许重试。
- 当结束成功时，iOS 应刷新记录和方案，再进入反馈/复盘后续入口。

### R13. 页面与布局

- iPhone 主页面应按小程序优先级固定展示签到、分组、积分、工具箱，并固定环节导航；低频工具由工具箱进入。
- iPhone 工具使用单一 item-driven sheet；sheet 内不得出现无法工作的八项工具 Picker，关键操作应固定在底部安全区。
- 现场深色背景上的正文和状态文字应满足清晰对比度，并使用现有品牌色 token。
- iPad 应使用主现场内容 + 右侧工具检查器，共享与 iPhone 相同的业务状态和工具组件。
- 当内容为空、加载中、保存中或失败时，页面应显示对应状态，不得以大片无语义空白 List 代替。
- 当动态字体增大时，关键计时、工具按钮和底部操作不应截断或互相遮挡。

### R14. 校验与发布边界

- 当提交实现时，Swift 单元测试应覆盖真实 action 名、请求 DTO、响应 DTO、顺序写入和环节计时切换。
- 当提交实现时，iPhone 与 iPad Simulator Debug 构建应通过，iPhone 现场主流程应完成逐工具运行态冒烟。
- 当提交实现时，云函数语法检查、小程序 `verify:all` 和 `git diff --check` 应通过。
- 在没有测试环境 EnvId、HTTPS 网关和有效令牌时，不得宣称真实 CloudBase E2E 已完成；必须明确剩余部署验证。

## 4. 设计规格

- Purpose：让培训师在高压现场快速判断当前环节、时间和下一动作，且所有成功状态都有可信数据来源。
- Aesthetic Direction：工业/工具型，强调可扫读、低干扰、明确状态。
- Color Palette：现场 `#1A1A2E`、品牌 `#4A7CF7`、成功 `#34C759`、危险 `#E5484D`、内容面 `#FFFFFF/#1C1E27`。
- Typography：沿用 San Francisco Dynamic Type，服从 iOS 平台可访问性和项目现有设计系统。
- Layout Strategy：顶部状态、中心计时、独立提醒、底部高频工具与环节导航；iPad 增加右侧检查器，不复制业务状态。

## 5. 约束与非目标

- 不修改小程序既有用户流程、action 名或参与者页面。
- 不新增覆盖全场次的 `saveSession` 大接口；优先复用现有细分 action。
- 不在本任务中部署 CloudBase、写入密钥或假设隐式 EnvId。
- 不逐像素复制小程序；保留符合 iPhone/iPad 的原生导航、动态字体和辅助功能。
- 不顺手重构现场范围之外的 iOS 页面或未关联云函数。
